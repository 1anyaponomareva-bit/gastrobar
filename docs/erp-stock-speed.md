## Причины задержки склада

1. **Анонимный `/erp/stock`**: «Загрузка…» 1.5–5 с, пока `/api/erp/state` тянет весь каталог и отвечает 401. На проде это **подтверждено повторно** (первый запрос db 4.7 с).
2. **Регион**: UI во Вьетнаме, serverless в `iad1`. Пустой ping уже ~0.3 с. Каждый API после логина добавляет ещё 0.5–1 с до базы.
3. **Водопад после входа**: `ErpShell` ждёт полный state (включая recipes/dishes), *потом* монтирует вкладку, *потом* список бьёт `/api/erp/documents` или `/api/erp/receipts`. После `erp_load_state` резать первый state на две поездки **хуже** (2 RTT вместо 1). Перекрытие списка со state — отдельный шаг в `ErpShell` / `docs.tsx`, не в этом diff.
4. **~16 PostgREST** на state. Комментарий ba8d8a7 «one database round trip» был неверен. При лимите соединений это 2–3 волны; на проде сейчас ближе к 1 волне.
5. **Поставки**: строки грузились чанками **по очереди**; списания — `Promise.all`. На проде после фикса не перезамерено.

Не в этой полосе: вёрстка списаний, печать/экспорт, FIFO, проведение инвентаризации, счета, каталог Staff.

## Что исправлено в ветке

1. `readAsAdmin`: нет cookie — **401 без БД**. Анонимный вход должен стать как ping (~0.3 с до формы), не 1.5–5 с. Залогиненный путь по-прежнему auth∥db. **На проде не действует, пока нет выкладки.**
2. SQL `erp_load_state` + вызов из `loadState` с откатом, если функции нет. Промах кэшируется **на 60 с**, затем RPC пробуется снова (миграция могла прийти после первого тёплого инстанса).
3. `/api/erp/receipts`: чанки строк параллельно, как у writeoffs.
4. Миграция `erp_load_state` добавлена в списки PGlite (`localDb.ts`, `testDb.ts`), иначе локальный next и `test-erp` жили на fallback из 16 запросов.

## Издателю

Миграция совместимая (только функция). Применить **до или вместе** с кодом. Если код выйдет раньше, инстанс 60 с ходит fallback, затем снова пробует RPC.

Файлы, которые эта ветка **не** трогала и которые нужны для большего выигрыша:

- `src/components/erp/ErpShell.tsx` — начать `/api/erp/documents` или `/api/erp/receipts` **вместе** со state (не вместо: два последовательных `erp_load_state` хуже одного).
- `src/components/erp/docs.tsx` / `ReceiptsPage.tsx` — только если список вшивают в prefetch-кэш оболочки.

Инфра (не код): колокация Vercel с регионом Supabase. С `iad1` один select уже 0.5–1 с, холодный — несколько секунд.

## Не замерено

- Холодный вход **с сессией** (openMs, первый экран остатков/поставок глазами).
- Save/post, карточка «Скорость связи» под админом.
- Реальный размер JSON state на проде.
- Регион проекта Supabase.
- Инвентаризация, проведение, FIFO, печать, мобильная вёрстка списаний.
- После выкладки этой ветки: повтор 401 `/api/erp/state` (должен быть без `db;dur`, как ping).
